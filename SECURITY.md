# Security Policy

## Supported versions

Security fixes are applied to the current published release line and `main`. Supported package versions are listed in release notes and maintained here as the support policy evolves.

## Reporting a vulnerability

Do not file a public issue for a suspected vulnerability. Use GitHub private vulnerability reporting when this repository is published. The repository owner must enable that feature and configure a monitored response path before public release.

Include the affected package/version, a minimal reproduction, impact assessment, and any proposed mitigation. We will acknowledge confirmed reports, assess impact, and coordinate a fix before public disclosure.

## Scope

Report vulnerabilities in the public packages, examples, workflows, documentation deployment, and release process. Customer accounts and hosted services will have a separate published reporting route before they are launched.
