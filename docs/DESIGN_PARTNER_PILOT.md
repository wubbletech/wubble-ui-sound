# Design Partner Pilot

## Objective

Prove that Wubble UI Sounds delivers a coherent, lightweight product-feedback system that developers can install and keep in a real staging application.

## Partner profile

- Product-minded front-end engineer or design engineer.
- Shipping a browser-based product with a staging environment.
- Can add a local package and static assets without extended procurement.
- Cares about product polish but does not have a dedicated sound designer.

Avoid using the first cohort for native-only products, long-form audio, game audio, or teams seeking a one-time stock asset library.

## Pilot flow

1. Baseline the existing product flow and identify three to six useful interaction events.
2. Export the Signal fixture or a tailored internal pack into the partner's staging application.
3. Record installation time, pack size, events wired, browser issues, and any modification needed.
4. Let the partner use the flow for at least one internal review cycle.
5. Ask for a keep/remove decision for each event and a request for any revision.
6. Hold a 30-minute debrief focused on observed behavior, not hypothetical features.

## Success threshold

Hosted Studio implementation is blocked until five independent design partners have agreed to trial the placeholder export workflow in real staging applications. Record each commitment before any hosted beta, customer-data connection, or customer-facing Studio claim.

The workflow is considered proven enough to begin the next Studio gate only when the five trials have been run, the installation outcome is recorded for each, and the team has reviewed retention, removal, revision, and repeat-use signals. The functional placeholder pack is deliberately for workflow validation only; commissioning or creating final production assets is deferred until this evidence review.

## Metrics

- Time from export command to a working staging integration.
- Export-to-valid-install rate.
- Percentage of selected events actually wired into the product.
- Pack size in bytes and change to application delivery budget.
- Regeneration or revision requests by event type.
- Number of partners that retain the pack through an internal review.
- Number that begin a second project or revision.

Do not collect customer application content, production user event data, credentials, or end-user audio behavior during the pilot.
